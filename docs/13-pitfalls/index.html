第13章 つまずき集と、次の一歩

Qt5 時代の記事との差分早見表、PyQt6 との違い、配布方法、そして公式ドキュメントの歩き方。ここから先は自力で進めます。

ひととおり終わりました。ここから先は、自分で調べながら進むことになります。 その助けになるものを集めておきます。

検索して出てきた記事のコードが動かないとき、まずこの表を見てください。 ほとんどのケースはここに当てはまります。

大事なのは右端の列です。 「エラーになる」ものより、「黙って動いてしまう」もののほうが厄介だからです。

😐 の行が、この教材でいちばん伝えたいところ

PySide6 には「寛容モード」という仕組みがあり、 Qt5 時代の短い enum の書き方を、内部で新しい形に読み替えて受け付けます。 エラーも警告も出ません。

ありがたい機能ではあるのですが、学習中には落とし穴になります。 古い記事を写して動いてしまうと、それが正しい書き方だと思い込んだまま先へ進んでしまうからです。

それでも最後まで書くべき理由は 3 つあります。

  • エディタの補完と型チェックが正しく効く
  • 同じコードを PyQt6 に持っていくと、そちらは容赦なく AttributeError になる
  • 寛容モードはあくまで移行期の救済措置で、将来なくなる可能性がある
この表は毎回、実物で確かめてから公開している

ここに書いた挙動は、Web の記事を写したものではありません。 このページを組み立てるたびに tools/check_claims.py が 実際の PySide6 に対して 1 行ずつ試し、食い違っていれば公開が止まるようにしています。

実を言うと、この教材の初稿では 😐 の行を「AttributeError になる」と書いていました。 PyQt6 の挙動を PySide6 の話として書いてしまっていたのです。 このチェックを入れたことで間違いに気づきました。

PyQt6 と PySide6 の違い

検索すると PyQt6 の記事も大量に出てきます。 この 2 つはほぼ同じもので、同じ Qt を別の会社が Python から使えるようにしたものです。

PySide6（この教材）PyQt6
作っているところQt 社（公式）Riverbank Computing 社
ライセンスLGPL / 商用GPL / 商用
シグナルの宣言Signal()pyqtSignal()
スロットの装飾子@Slot()@pyqtSlot()
プロパティProperty()pyqtProperty()
短い enum（Qt.AlignCenter） 寛容モードで動く 厳格。AttributeError になる
それ以外の APIほぼ同一
PyQt6 の記事を PySide6 に読み替える

PyQt6 → PySide6、pyqtSignal → Signal、 pyqtSlot → Slot。この 3 つを置き換えるだけで、たいてい動きます。

ライセンス面では、クローズドソースのソフトを配布する予定があるなら LGPL の PySide6 のほうが扱いやすいです（GPL は原則ソース公開が必要）。

アプリが固まるとき — 重い処理の扱い

第 2 章のイベントループの図で触れた話です。 スロットの中で時間のかかる処理をすると、その間 UI は完全に止まります。

解決策は主に 3 つあります。

方法向いている場面
QThread / QThreadPool ＋ QRunnable CPU を使う処理、既存の同期的なライブラリを呼ぶとき
QProcess 外部コマンドを実行するとき
QtAsyncio（PySide6 に同梱） Python の asyncio と組み合わせたいとき
別スレッドから画面を触ってはいけない

Qt では、ウィジェットの操作はすべてメインスレッドから行う決まりです。 別スレッドから label.setText() を呼ぶと、動くこともありますが、 いずれ不定期にクラッシュします。 結果はシグナルで送り、メインスレッド側のスロットで画面を更新してください。 シグナルはスレッドをまたいでも安全に届きます。

配布する

Python が入っていない人に渡すには、実行ファイルにまとめます。 定番は PyInstaller です。

オプション意味
--windowed実行時に黒いコンソール窓を出さない（GUI アプリでは必須）
--onefile1 つの exe にまとめる。起動は遅くなる
--icon=app.icoアイコンを指定する
配布でつまずきやすい点
  • クロスコンパイルはできない。Windows 版は Windows で、macOS 版は macOS でビルドする必要があります
  • ファイルサイズは大きい。Qt を丸ごと含むので数十〜百数十 MB になります
  • 相対パスが変わる。画像などを読む場合、sys._MEIPASS を見る必要があります
  • macOS では署名と公証をしないと「開発元を確認できません」と警告が出ます

公式ドキュメントの歩き方

最終的にいちばん頼りになるのは公式のリファレンスです。読むコツがあります。

  • C++ 版のドキュメントを読む。 doc.qt.io/qt-6 のほうが情報量が多く、更新も早いです。 QWidget::setEnabled() は Python では widget.setEnabled()、と読み替えるだけです
  • Python 版は doc.qt.io/qtforpython-6。 Python 特有の書き方（戻り値がタプルになる、など）はこちらで確認します
  • クラスのページでは、まず「Signals」の節を探す。 そのウィジェットで何ができるかは、シグナルの一覧を見るのがいちばん早いです
  • 継承元もたどる。 QPushButton のページに載っていないメソッドは、 QAbstractButton や QWidget のページにあります

おわりに

ここまでで、ウィンドウを出し、部品を並べ、操作に反応し、 データを表示し、見た目を整え、保存して、配布するところまで通しで扱いました。 これは「小さな道具を自分のために作る」には十分な範囲です。

GUI づくりで伸びるいちばんの近道は、自分が本当に欲しいものを 1 つ作ることです。 毎日使っているスクリプトに画面を付ける、それだけで十分です。 その過程で必ず何かに詰まりますが、詰まった内容は、この教材の目次のどこかに対応しています。 戻ってきて引いてください。
