はじめに — この教材の歩き方

Rust が何のための言語で、なぜ「難しい」と言われるのか。そして C# が書けるあなたが、どこを速く飛ばし、どこで立ち止まるべきかを先に決めます。

この教材が解こうとしている問題

Rust の入門でいちばん多い挫折は、文法が難しいことではありません。 「記事のとおりに書いたのに動かない」ことです。

Rust は 6 週間ごとに新しい版が出て、外部ライブラリの作法も年単位で変わっていきます。 そのため Web 上の記事は、書かれた時点では正しくても、いま試すと通らないことがよくあります。 初心者にとって最悪なのは、エラーメッセージを読んでも 「自分が間違えたのか、記事が古いのか」が判断できないことです。

やっかいなのは「エラーの理由がずれる」こと

実例を 1 つ出します。入門の定番である数当てゲームは、乱数の rand クレートを使います。 ネット上の記事はほぼすべて次の書き方です。

これは rand 0.8 の書き方で、いまは動きません。 そこまでは、まだ親切なほうです。本当に厄介なのはこの次です。 「0.9 で rng() と random_range() に変わった」と知って直しても、 やはり動きません。しかも出るエラーが use rand::Rng; を書いているのに 「そんなメソッドはありません」という、意味の分からないものになります。

答えは付録に書きますが、ここで言いたいのは この種の間違いは、Web の記事を読んで書くかぎり避けられないということです。

そこでこの教材は、書き方をひとつ決めました。 本文に載っているものは、書き写したものではなく、実際に動かした結果そのものです。

  • コードは rust/examples/ にある実ファイルが唯一の原本です。ページを組み立てるときに、その中身をそのまま読み込んで表示しています。
  • 「コンパイルが通らない例」も、本当に通らないことを機械的に確かめています。「これは E0382 になります」と書いた例は、全部実際に rustc に通して、そのエラーコードが出ることを検証したものです。
  • ターミナルの画面は、実際にコマンドを走らせて捕獲した出力です。色まで本物です。
  • 外部クレートについての記述も、実際にそのクレートを取ってきてコンパイルして確かめています。

つまり「本文とコードと画面が食い違う」ことが、構造的に起きません。 安心して、書いてあるとおりに手を動かしてください。

実測と再現の区別

ターミナルの画面には 実測 か 再現 のバッジが必ず付いています。

  • 実測 … 実際にコマンドを走らせて捕獲したもの。
  • 再現 … Windows のインストーラのように、この教材をビルドしている環境では出せない画面。 公式の情報に基づいて再現したもので、何に基づくかを必ずキャプションに書いています。

なお実測の画面についても、パスの表記だけは Windows の形に直しています （target/debug/hello → target\debug\hello.exe など）。 エラーメッセージの本文・バージョン番号・かかった秒数には手を入れていません。

Rust とはなにか

Rust は、システムを書くための言語です。 OS やブラウザのように「速さとメモリの効率が要る」領域で、 それでいてメモリまわりの事故を起こさないことを目指して作られました。

Firefox のレンダリング部分、Windows のカーネルの一部、Linux カーネルのドライバ、 Discord や Cloudflare のサーバ、Deno や Node.js の周辺ツール、 そして ripgrep や bat のようなコマンドライン道具が Rust で書かれています。

図の右端を見てください。Rust が「難しい」と言われる理由は、ここに全部あります。 C# なら実行してから分かっていた不具合が、コンパイル時に前倒しで出てくるのです。 総量としては減るのですが、最初にまとめて来るので重く感じます。

GC が無いとどうなるのか

C# はガベージコレクタが「もう誰も見ていないオブジェクト」を見つけて捨ててくれます。 Rust にはそれがありません。かわりに 「値には持ち主がひとりだけいる」という規則をコンパイラが強制し、 持ち主がいなくなった瞬間に片付けます。

この規則が第 6 章の所有権です。この教材でいちばん大事な章であり、 ここを越えれば残りはずっと楽になります。

C# が書ける人にとっての Rust

あなたは C# が書けるので、この教材では次のことを説明しません。

  • 関数とは何か、引数とは何か
  • クラス、インターフェース、ジェネリクスの考え方
  • ビルドとは何か、パッケージ管理とは何か

そのかわり、C# との対応関係と、 C# の直感がかえって邪魔になる箇所を各章で名指しします。 後者のほうが大事です。似ているのに違うものが、いちばん時間を食うからです。

この囲みの意味

この C# の印が付いた囲みでは、C# との対応と食い違いを扱います。 たとえば次のようなものです。

C#Rust注意
varletRust は既定で書き換え不可
nullOption<T>null という概念自体が無い
例外 / try-catchResult<T, E> / ?失敗は戻り値で返す
IDisposable / usingDrop書き忘れようがない
インターフェーストレイト他人の型にも後から実装できる
LINQイテレータほぼそのまま対応する
string（UTF-16）String（UTF-8）「長さ」の意味が変わる
async / Taskasync / Future走り始める瞬間が違う

下の 3 つが特に危険です。似ているので気づかないまま間違え、 しかも間違いが表に出るまで時間がかかります。

この教材が前提とする版

ページの上部にあるバッジに、この教材が検証された正確な版が出ています。 これは執筆時に手で書いたものではなく、ページを組み立てた環境から自動で読み取った実際の値です。 エディションも、実際に cargo new を走らせて生成された Cargo.toml から読んでいます。

エディションって何？ 版とは別物？

Rust には エディションという仕組みがあります。 2015 / 2018 / 2021 / 2024 の 4 つがあり、 新しいコンパイラはどのエディションのコードもコンパイルできます。

つまり「新しい Rust を入れたら古いコードが動かなくなった」が起きません。 エディションはプロジェクトごとに Cargo.toml で選びます。 いまの cargo new は 2024 を書き込みます。

版（1.97 のような番号）は 6 週間ごとに上がり、エディションは数年に 1 度です。 この教材は最新の stable と 2024 エディションで書いています。

この教材の読み方

  • 第 7 章（借用） — 第 6 章と対になっています。2 つで 1 セットと考えてください。
  • 第 14 章（トレイト） — インターフェースに似ていますが、できることが違います。
  • 第 20 章（async） — C# の async の知識がそのまま通じません。ここは必ず読んでください。

逆に、第 4 章と第 5 章（変数・制御フロー）は C# の知識でほとんど読み飛ばせるように、差分だけを短く書いてあります。

この章のまとめ

  • Rust 入門の最大の敵は「古い情報」。この教材は実行済みのコードと実測の出力でそれを避ける。
  • 「通らない例」も実際にコンパイルして、エラーコードまで検証している。
  • Rust は GC を持たず、コンパイル時の検査で安全と速さを両立させる。だから最初が重い。
  • C# の知識は大いに使える。ただし文字列・async・インターフェースの 3 つは要注意。
  • エディションは版とは別物。新しいコンパイラでも古いコードは動く。
