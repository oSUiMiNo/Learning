第3章 Cargo と最初の一本 — dotnet CLI に相当するもの

`cargo new` から `cargo run` まで。`Cargo.toml` は .csproj、crates.io は NuGet に当たります。エディションという Rust 独自の概念もここで。

Cargo は Rust の dotnet コマンドに当たるものです。 プロジェクトを作り、依存を解決し、ビルドし、テストを走らせ、 ドキュメントを生成します。これ 1 つで一通り済みます。

C# の dotnet new console から dotnet run までと、 やることはほとんど同じです。まず作って動かしてしまいましょう。

プロジェクトを作る

PowerShell で作業したいフォルダに移り、cargo new を打ちます。

できたものは 2 ファイルだけです。Cargo.toml を見てみます。

行意味
[package]このパッケージ自身の情報
nameパッケージ名。実行ファイルの名前にもなる
version版。セマンティックバージョニング
editionエディション。いまは 2024
[dependencies]依存クレートを書く場所。最初は空
Cargo.toml と .csproj

packages.lock.jsonCargo.lock
NuGetcrates.io

ソリューション（.sln）ワークスペース

大きな違いは、.csproj のようにファイルを列挙しないことです。 Cargo は src/main.rs を入口として、 mod 宣言をたどって必要なファイルを見つけます（第 16 章）。 「ファイルを追加したのにビルドに含まれない」という事故は起きません。

動かす

cargo run と打つだけで、ビルドと実行がまとめて行われます。

出力の 3 行を見てください。

行意味
Compilingコンパイル中。パッケージ名と版、場所が出る
Finished完了。dev プロファイル（最適化なし・デバッグ情報あり）だと明記されている
Runningどの実行ファイルを起動したか

そして 2 回目の実行では Compiling が消えています。 Cargo は変更がなければ再ビルドしません。

Hello の中身を読む

生成された main.rs は 3 行です。それに少し足したものがこれです。

このファイルだけで、Rust のプログラムの形がほぼ全部見えています。

main が入口

C# の Main と同じですが、クラスの中に入れる必要はありません。 ファイルの一番上に置けます。

println! の ! はマクロの印

! が付いているものはマクロです。 関数ではなく、コンパイル時にコードへ展開されます。

書式指定の対応
C#Rust
$"こんにちは {name}"format!("こんにちは {name}")
Console.WriteLine(...)println!(...)
Console.Write(...)print!(...)
string.Format("{0}", x)format!("{}", x)
obj.ToString(){}（Display トレイト）
デバッグ表示{:?}（Debug トレイト）
x.ToString("F3"){:.3}

C# の文字列補間 $"..." と同じ感覚で println!("{name}") と書けます。 これは Rust 2021 から入った書き方です。 古い記事は println!("{}", name) と書いていますが、どちらも今も有効です。

セミコロンの有無に意味がある

add 関数の中を見てください。a + b にセミコロンが付いていません。

Rust ではブロックの最後の式が、そのブロックの値になります。 セミコロンを付けると「文」になり、値を返さなくなります。 第 5 章で詳しく扱いますが、ここでは 「最後の行のセミコロンを消し忘れると型エラーになる」ことだけ覚えてください。

最頻出のミス: 最後にセミコロンを付けてしまう

次のように書くと、「i32 を返すはずなのに () を返している」 という E0308 になります。

() は「ユニット型」で、C# の void に当たります。 エラーに expected `i32`, found `()` と出たら、 まず最後の行のセミコロンを疑ってください。

依存クレートを足す

crates.io にあるライブラリは cargo add で足せます。 乱数を扱う rand を入れてみます。

+ が付いているのが有効になった機能、 - が無効のままの機能です。 Rust のクレートは機能を選んで削れるので、 使わない部分をビルドしなくて済みます。

cargo add は昔は無かった

cargo add が Cargo に標準で入ったのは 1.62（2022 年）です。 それより前は cargo-edit という別のツールを入れる必要がありました。

そのため古い記事には 「cargo install cargo-edit してから cargo add」 と書かれていることがあります。いまは不要です。 あるいは「Cargo.toml を手で編集する」と書かれていることもありますが、 それも今でも正しい方法です（cargo add がやってくれるのと同じことです）。

依存にまつわるコマンド
コマンドやること
cargo add rand最新版を足す
cargo add serde --features derive機能を指定して足す
cargo remove rand外す
cargo updateCargo.lock を更新する
cargo tree依存関係を木で見る
cargo info randクレートの情報を見る

Cargo.lock は何のためにあるか

cargo build すると Cargo.lock ができます。 これは「実際に使った版を 1 つずつ記録したもの」です。

Git に入れるか
実行ファイルを作るプロジェクト入れる。誰がビルドしても同じ結果になる
ライブラリ入れないのが慣習。使う側の都合に合わせる
やってみよう
  1. cargo new hello して cargo run するところまでを、自分の手で通してください。
  2. add 関数の a + b にセミコロンを付けて cargo build し、E0308 が出ることを確認してください。わざとエラーを出す練習は無駄になりません。
  3. cargo run -- こんにちは のように引数を付けて実行し、-- の意味を確かめてください（今のコードは引数を読まないので何も変わりませんが、エラーにもなりません）。

この章のまとめ

  • cargo new → cargo run で始まる。作られるのは Cargo.toml と src/main.rs だけ。
  • Cargo.toml は .csproj、crates.io は NuGet に当たる。ファイルの列挙は不要。
  • ! が付いているのはマクロ。println!("{name}") は C# の $"{name}" と同じ感覚で使える。
  • ブロックの最後の式が戻り値。セミコロンを付けると値を返さなくなる。
  • 依存は cargo add。昔は別ツールが必要だったが、今は標準。
