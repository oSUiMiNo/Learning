第2章 エディタの準備 — rust-analyzer に働かせる

Rust は「エディタが賢いと一気に楽になる」言語です。型を目で見えるようにして、コンパイル前に間違いを潰せる状態を作ります。

先に結論を書きます。Rust はエディタの支援があるかどうかで、難易度がまるで変わります。

理由は単純です。Rust は型推論が強く、コードには型がほとんど書かれていません。 しかも所有権と借用の規則があるので、 「この変数はいま何型で、借りているのか持っているのか」が分かるかどうかが、 そのまま読みやすさになります。エディタがそれを教えてくれれば、 コンパイルする前に間違いに気づけます。

VS Code と rust-analyzer

公式に推奨されている構成は VS Code ＋ rust-analyzer 拡張です。 拡張は 1 つだけ入れれば十分です。

項目値
拡張の名前rust-analyzer
発行元The Rust Programming Language
拡張 IDrust-lang.rust-analyzer

コマンドで入れることもできます。

「Rust」という名前の拡張を入れないこと

以前は rust-lang.rust という名前の拡張がありました（中身は RLS という古い仕組み）。 これはすでに非推奨で、開発も止まっています。

古い記事には「Rust 拡張を入れる」と書かれていることがありますが、 いま入れるべきなのは rust-analyzer です。 名前が似ているので、発行元と ID で確かめてください。 両方入れると競合して補完がおかしくなります。

ほかのエディタでもよい場合

rust-analyzer は言語サーバ（LSP）なので、対応しているエディタなら同じ支援が受けられます。

  • RustRover（JetBrains 製）… Rust 専用の IDE。非商用なら無料で使えます。IntelliJ 系に慣れているならこちら。
  • Zed … rust-analyzer を内蔵しており、設定なしで動きます。
  • Neovim / Helix … LSP の設定を書けば同じように動きます。

この教材のコードはエディタに依存しないので、好きなものを選んでください。

入れると何が変わるか

rust-analyzer が効いていると、次のことが起きます。 このうち最初の 2 つが、Rust を学ぶうえで決定的に効きます。

できることなぜ効くか
型が薄い文字で表示される
（インレイヒント）		 書いていない型が目に見える。let x = ... の x が String なのか &str なのかが即分かる
保存前にエラーが出る 所有権の違反がその場で赤くなる。コンパイルを待たなくてよい
メソッド補完 そのトレイトが実装されているものだけが出るので、探しやすい
定義へ移動（F12） 標準ライブラリの中身まで読める。実装が全部読めるのは Rust の強み
クイックフィックス .clone() の挿入や use の追加を提案してくれる
インレイヒントを必ず有効にしておく

型が薄く表示される機能は、Rust の学習では特に効きます。 既定で有効ですが、消えている場合は設定を確認してください。 Ctrl + , で設定を開き、 editor.inlayHints.enabled を on にします。

Ctrl + Alt を押している間だけ表示する、という設定 （onUnlessPressed）も便利です。

おすすめの設定

プロジェクトの .vscode/settings.json に置いておくと、 保存するだけで整形と静的解析がかかるようになります。

3 行目の check.command を clippy にしておくのが要点です。 既定の cargo check より多くのことを指摘してくれます。

付いてくる道具たち

rustup を入れた時点で、次のコマンドが使えるようになっています。 エディタからも呼ばれますが、意味を知っておくと役に立ちます。

コマンドやることC# なら
cargo buildビルドするdotnet build
cargo runビルドして実行するdotnet run
cargo check型検査だけして、実行ファイルは作らない—
cargo testテストを走らせるdotnet test
cargo fmt整形するdotnet format
cargo clippy書き方の助言をもらうアナライザ / IDE0xxx
cargo doc --open自分のコードのドキュメントを作って開くDocFX 相当
cargo add <名前>依存を追加するdotnet add package
cargo check は速い

cargo check は型検査だけを行い、実行ファイルを作りません。 そのぶん cargo build よりずっと速いので、 「まず通るかどうかだけ知りたい」ときに便利です。 rust-analyzer が裏で走らせているのもこれです。

clippy は何を言ってくるのか

clippy は「動くけれど、こう書いたほうがよい」を教えてくれます。 実際に少し雑なコードを書いて、走らせた結果がこれです。

注目してほしいのは help: の行です。 ただ「駄目だ」と言うのではなく、どう書けばよいかまで示してくれます。 指摘の意味が分からないときは、末尾の URL を開けば解説が読めます。

自動で直してもらう

出力の最後に書いてあるとおり、直せるものは自動で直せます。

納得できない指摘は無効にできます。理由をコメントに書いておくと後で助かります。

clippy は「うるさいアナライザ」ではない

C# のアナライザは、チームによっては切ってしまうこともあります。 Rust の clippy は初心者にとって教師として機能します。

「なぜこの書き方が良くないのか」を毎回教えてくれるので、 指摘に従っているうちに Rust らしい書き方が身につきます。 この教材のサンプルコードも、全部 clippy の指摘ゼロで通しています。

やってみよう
  1. rust-analyzer を入れて、適当な let x = 5; の行を書いてみてください。x の後ろに : i32 が薄く出れば成功です。
  2. let s = "hello".to_string(); と書いて、s の型が String と出ることを確認してください。let s = "hello"; なら &str になります。この違いが第 8 章の主題です。
  3. わざと let x = 5; x = 6; と書いて、保存する前に赤い波線が出ることを確認してください。

この章のまとめ

  • 入れるのは rust-analyzer（rust-lang.rust-analyzer）。古い「Rust」拡張は入れない。
  • インレイヒントで型が見えるようにすると、Rust の学習は一気に楽になる。
  • rust-analyzer.check.command を clippy にしておく。
  • cargo check は型検査だけなので速い。
  • clippy は直し方まで教えてくれる教師。逆らわずに従うのが早い。
