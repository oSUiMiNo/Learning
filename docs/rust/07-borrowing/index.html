第7章 借用と参照 — 貸し借りの規則

所有権を渡さずに値を使わせるのが借用です。「書き込みできる参照は同時に 1 つだけ」という一行が、データ競合を根こそぎ防ぎます。

前の章で「関数に渡すと所有権も渡ってしまう」問題が出ました。 その解決策が借用です。所有権を渡さずに、値を使わせます。

規則はたった 2 行です。この 2 行が、データ競合と 「反復中にコレクションを変更した」系の不具合を根こそぎ防ぎます。

読む借用

& を付けると「借りる」になります。所有権は動きません。

引数は &[T] や &str で受けるのが基本

読むだけの引数は、&Vec<i32> より &[i32]、 &String より &str で受けるのが定石です。 そのほうが渡せるものが増えるからです。

受け方渡せるもの
&Vec<i32>Vec だけ
&[i32]Vec、配列、スライス
&StringString だけ
&strString、文字列リテラル

&Vec で受けていると clippy が 「&[T] にしなさい」と教えてくれます。

書く借用

書き換えたいときは &mut です。 貸す側にも mut が必要な点に注意してください。

mut を付け忘れると、こうなります。

「メソッドを呼んだだけなのに mut がないと言われる」

push、sort、insert のように 中身を変えるメソッドは &mut self を要求します。 つまりメソッドを呼ぶだけでも書く借用が発生します。

エラーに cannot borrow ... as mutable と出たら、 変数の宣言に mut を足すだけで直ります。

2 つの規則を破ってみる

規則の 1 つ目、「&mut は 1 本だけ」を破るとこうなります。

2 つ目、「読む借用と書く借用は同席できない」を破るとこうです。

これは C# の「反復中の変更」と同じ問題

C# で次のように書くと、実行時に InvalidOperationException が飛びます。

Rust の E0502 はまったく同じ問題を、コンパイル時に止めたものです。 C# は「列挙中に変更されたかどうか」を実行時のバージョン番号で見張っていますが、 Rust は借用の規則で構造的に防いでいます。

つまりこのエラーは、Rust がうるさいのではなく C# なら本番で落ちていた不具合を、手元で見つけてくれたということです。

借用はいつ終わるのか

ここが分かると、借用検査が急に扱いやすくなります。 借用はスコープの終わりではなく、「最後に使った場所」で終わります。

これは実際に通ります。通ることを確かめた例として置いてあります。

この教材では、こうした「通る例」もコンパイルして確認しています。 上のファイルの先頭に expect: ok と書いてあるのがその印です。

古い記事の「Rust は厳しすぎる」を信じないこと

2018 年より前に書かれた記事は、この改良より前のものです。 「借用検査が厳しくて書けない」「一度変数に入れないと通らない」といった記述は、 いまは当てはまらないことがあります。

対処法は単純です。まず素直に書いて、コンパイルしてみる。 通ればそれでよいのです。

スライス — 借用の応用

スライスは「一部分を借りる」書き方です。コピーは起きません。

Span<T> / ReadOnlySpan<T> に相当

C# の Span<T> とほぼ同じ考え方です。 どちらも「コピーせずに一部を見る」ためのもので、 元のデータより長生きできないという制約も同じです。

違うのは、C# では Span を使うのが最適化のための選択なのに対し、 Rust ではスライスが標準的な受け渡し方法だという点です。

あと 2 つのよく出るエラー

借用まわりで残り 2 つ、よく踏むものがあります。

借用検査で行き詰まったときの手順

慣れるまでは必ず詰まります。次の順に試してください。

  1. 借用の範囲を狭める。借りた値を早く使い切る、あるいは {} で囲む。
  2. 値を取り出してしまう。let last = *v.last().unwrap(); のように * で中身をコピーすれば借用は終わる。
  3. clone() する。遅くなるが動く。まず動かすことが大事。
  4. 設計を変える。関数を分ける、所有権を渡す形にする、第 18 章の Rc/RefCell を使う。

1 から順に試して、通ったところで止めてよいのです。 最初から最適な形を狙わなくて構いません。

やってみよう
  1. examples/07-borrowing を動かしてください。
  2. let first = &numbers[0]; を書いた直後に numbers.push(4); を置き、その後で first を使うとエラーになることを確認してください。使う順番を入れ替えると通ります。
  3. double_all の引数を &mut [i32] から &[i32] に変えて、どんなエラーになるか見てください。
  4. &all[1..4] の範囲を &all[1..9] にして実行してください。これはコンパイルは通り、実行時に panic します。範囲の検査は実行時であることが分かります。

この章のまとめ

  • &T は読む借用、何本でも作れる。&mut T は書く借用、同時に 1 本だけ。
  • 読む借用と書く借用は同席できない。C# の「反復中の変更」をコンパイル時に止めたもの。
  • 借用はスコープの終わりではなく最後に使った場所で終わる（NLL）。
  • 引数は &[T] / &str で受けるのが定石。
  • 行き詰まったら「範囲を狭める → 値を取り出す → clone する → 設計を変える」の順に試す。
