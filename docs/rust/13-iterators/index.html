第13章 イテレータとクロージャ — LINQ に似ている話

`Where` は `filter`、`Select` は `map`。遅延評価まで同じです。この章はたぶん、C# 経験がいちばん効きます。

この章は、たぶん C# の経験がいちばん効きます。

LINQ を知っていれば、Rust のイテレータはほぼそのまま読めます。 遅延評価という性質まで同じです。名前が違うだけで、考え方は同一です。

無いのは Distinct・GroupBy・Average の 3 つだけです。 どれも fold か itertools クレートで書けます。

そのまま読める

違うのは 2 点だけです。

  • 先頭に .iter() が要る（C# はコレクションが直接 IEnumerable）
  • 最後の collect() に何に集めるかの型が必要
collect() には型を教える

collect() は Vec にも HashMap にも String にもなれるので、型を書かないと決まりません。

::<> という記法は「ターボフィッシュ」と呼ばれます。 type annotations needed と言われたら、これを足してください。

3 種類の iter

第 12 章の for の 3 通りと同じ区別です。

書き方要素の型元のコレクション使う場面
.iter()&T残るふつうはこれ
.iter_mut()&mut T残る中身を書き換える
.into_iter()T消える中身を別の場所へ移す
クロージャの引数が &&T になる話

.iter().filter(|p| ...) と書くと、 p の型は &&T（参照の参照）になります。 iter() が &T を出し、filter がさらに借りるからです。

ふだんは気にしなくてよく、Rust が自動で参照を外して p.department のように書けます。 ただし比較でエラーが出たときは、* や & の数を疑ってください。

遅延評価も同じ

実行してみると、遅延評価が目で見えます。

LINQ と同じ落とし穴も同じように存在する

C# で「IEnumerable を 2 回なめたら 2 回クエリが走った」という経験があると思います。 Rust ではそもそも 2 回なめられません。

イテレータは next() を呼ぶと進む「使い切り」のものなので、 消費するメソッドは所有権をもらいます。 2 回使いたければ collect() して Vec にするか、 もう一度 v.iter() から作り直します。

C# なら実行時に静かに 2 回走って遅くなるところが、 Rust ではコンパイルエラーになる、ということです。

GroupBy が無い場合の書き方

itertools を入れれば楽になる

itertools クレートを足すと、LINQ に近いメソッドが増えます。

itertoolsLINQ
unique()Distinct()
chunk_by()GroupBy()（隣り合うものだけ）
into_group_map()GroupBy()（全部）
sorted()OrderBy()
join(", ")string.Join()

失敗しうる変換をまとめる

これは C# にない、便利な性質です。 Vec<Result<T, E>> を Result<Vec<T>, E> にたためます。

C# だと自分で書くしかない

C# で「全部変換できたら成功、1 つでも駄目なら失敗」を書くには、 ループを回して例外を捕まえるか、TryParse を並べる必要があります。

Rust では collect() の型を Result<Vec<_>, _> にするだけです。 しかも最初の失敗で打ち切ります（残りは処理しない）。 Option でも同じことができます。

クロージャ

C#Rust
x => x * 2|x| x * 2
(x, y) => x + y|x, y| x + y
x => { ...; return y; }|x| { ...; y }
() => 42|| 42
move を付けると捕まえた値をもらう

クロージャは既定で、使っている変数を借用します。 move を付けると所有権をもらいます。

スレッドに渡すとき（第 19 章）や、 クロージャを関数から返すときには move が必要になります。 「closure may outlive the current function」と言われたら move を足す と覚えておいてください。

3 つのクロージャのトレイト
トレイト捕まえ方何回呼べるか
Fn&T で借りる何回でも
FnMut&mut T で借りる何回でも（状態が変わる）
FnOnce所有権をもらう1 回だけ

C# の Func<T, R> / Action<T> に当たりますが、 Rust は「捕まえた値をどう扱うか」でさらに 3 つに分かれます。 ふだんはコンパイラが選んでくれるので、意識するのは 引数の型として書くときだけです。

  1. examples/13-iterators を動かして、遅延評価が起きている箇所を目で確認してください。
  2. collect() の型注釈を消して、どんなエラーになるか見てください。
  3. 「開発部の平均給与」を求めるコードを書いてください（filter → map → sum と count）。
  4. C# の people.Select((p, i) => $"{i}: {p.Name}") に相当するコードを enumerate() で書いてください。
  5. let iter = v.iter(); iter.count(); iter.count(); と書いて、2 回使えないことを確認してください。

この章のまとめ

  • Where→filter、Select→map、ToList→collect。LINQ の知識がそのまま使える。
  • 遅延評価も同じ。collect や sum が引き金。
  • collect() には集める先の型を教える（ターボフィッシュ ::<>）。
  • iter()（借りる）/ iter_mut() / into_iter()（もらう）の 3 種類。
  • イテレータは使い切り。2 回なめようとするとコンパイルエラー。
  • Vec<Result> を Result<Vec> にたためる。C# に無い便利さ。
  • Distinct / GroupBy は標準に無い。fold か itertools で。
