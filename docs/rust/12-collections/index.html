第12章 コレクション — Vec と HashMap

`List<T>` は `Vec<T>`、`Dictionary<K,V>` は `HashMap<K,V>`。対応は素直ですが、借用の規則がここで初めて実戦になります。

この章は対応表でほとんど済みます。 List<T> は Vec<T>、Dictionary<K, V> は HashMap<K, V>。 名前が違うだけです。

ただし 1 つだけ新しいことがあります。 ここで初めて、借用の規則が実戦になります。 コレクションは「読みながら書き換えたくなる」ものなので、第 7 章の話が本当に効いてきます。

HashMap は use が必要

Vec と String は最初から使えますが、 HashMap などは use を書く必要があります。

忘れると cannot find type `HashMap` in this scope と言われます。 rust-analyzer が入っていれば、クイックフィックスで自動的に足してくれます。

Vec の基本

contains に & が付くことに注意してください。 値を借りて比べるだけなので、所有権は要らないからです。

添字と get の使い分け

C# の list[i] は範囲外で ArgumentOutOfRangeException を投げます。 Rust の v[i] は panic します。挙動は同じです。 落ちてほしくない場面では get() を使ってください。

HashMap の基本

Dictionary との違い
C#Rust違い
dict[key]map[&key]どちらも無いと落ちる
dict.TryGetValue(k, out v)map.get(&k)out 引数が要らない
dict.ContainsKey(k)map.contains_key(&k)
dict[k] = vmap.insert(k, v)Rust は古い値を Option で返す
dict.Remove(k)map.remove(&k)同じく古い値を返す
GetOrAdd（ConcurrentDictionary）map.entry(k).or_insert(v)下で説明

TryGetValue の out 引数が Option の戻り値になるのが、 いちばん気持ちのよい対応です。

entry API — 「無ければ入れる」

C# で「あれば足す、無ければ作る」を書くと、こうなりがちです。

entry のよく使う形
書き方意味
.entry(k).or_insert(v)無ければ v を入れる
.entry(k).or_default()無ければ型の既定値を入れる
.entry(k).or_insert_with(|| 重い計算())無いときだけ計算する
.entry(k).and_modify(|v| *v += 1).or_insert(1)あれば更新、無ければ挿入

or_insert は「入った値への &mut」を返すので、 * で中身を書き換えられます。 グループ化や集計を書くときの定番です。

HashMap の順序は決まっていない

HashMap をなめると、出てくる順番は毎回変わりえます。 Rust はハッシュの初期値を実行ごとにランダム化しているためです （ハッシュ衝突攻撃を防ぐ目的）。

順番を決めたいなら、明示的に並べるか BTreeMap を使ってください。

C# の Dictionary も順序は保証されませんが、 実装の都合で「だいたい挿入順」になることがあります。 そこに頼ったコードは Rust では通用しません。

ここで借用が効いてくる

コレクションを扱うと、必ずこれに当たります。

直し方は、借用を先に終わらせることです。

「なめながら消す」を書きたいとき

C# で foreach 中に Remove すると例外になるので、 ふつうは条件に合うものを別のリストに集めてから消します。 Rust には専用のメソッドがあります。

やりたいこと書き方
条件に合うものだけ残すv.retain(|x| *x > 0)
条件に合うものを抜き出すv.extract_if(..)
全部取り出して空にするv.drain(..)
中身を全部置き換える*v = 新しい Vec

retain は C# の RemoveAll に当たります。 「消す」のではなく「残す」条件を書く点に注意してください。

所有権をもらう繰り返しと、借りる繰り返し

for の書き方が 3 通りあります。ここは C# に無い区別です。

書き方もらうもの後で Vec を使えるか
for x in &v&T（借用）使える
for x in &mut v&mut T（書ける借用）使える
for x in vT（所有権）使えない
for x in v と書くと Vec が消える

C# の foreach (var x in list) の後も list は使えます。 Rust で for x in v と書くと、v の所有権が for に移ります。

& を 1 文字足せば直ります。 ふだんは for x in &v と書く癖にしておくのが無難です。

逆に「中身を取り出して別の場所へ移したい」ときは、 所有権をもらう形が正解になります。

全体を動かす

やってみよう
  1. examples/12-collections を動かしてください。
  2. HashMap の出力を何度か実行して、キーの順番が変わることを確認してください（環境によっては変わらないこともあります）。
  3. for w in words の & を消して、E0382 を出してください。
  4. 単語の出現回数を数えるコードを entry().or_insert(0) で書いてみてください。"a b a c b a".split(' ') を使うと楽です。
  5. numbers[99] を実行して、panic のメッセージを見てください。numbers.get(99) との違いが分かります。

この章のまとめ

  • Vec＝List、HashMap＝Dictionary。名前が違うだけ。
  • 取り出しは Option を返す（get）。添字は範囲外で panic。
  • entry().or_insert() で「無ければ入れる」が 1 行で書ける。
  • HashMap の順序は決まっていない。並べたいなら BTreeMap。
  • for x in &v は借りる、for x in v は所有権をもらう。& を付ける癖を。
  • 「なめながら消す」は retain / drain。
