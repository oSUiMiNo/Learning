第21章 実践 — CLI ツールを 1 本作って配る

ここまでの全部入り。引数解析・ファイル読み書き・JSON・エラー処理を組み合わせて、単体で配布できる実行ファイルまで持っていきます。

ここまでの全部入りです。ToDo を管理する小さな CLI ツールを作り、 単体で配布できる実行ファイルまで持っていきます。

使うものは 3 つのクレートだけです。 どれも Rust では定番で、この組み合わせを覚えておけば ほとんどのコマンドライン道具が書けます。

クレート役目C# なら
clap引数の解析とヘルプの生成System.CommandLine
serde ＋ serde_jsonJSON との相互変換System.Text.Json
anyhowエラー処理を楽にする—

準備

--features derive が要点です。 これを付けると属性を書くだけで引数解析や JSON 変換が生成されます。

clap は v3 と v4 で書き方が違う

clap は v3 → v4 で derive の API が変わりました。 古い記事には次のような書き方が載っています。

v4 では #[command(...)] と #[arg(...)] に分かれました。

clap(...) と書かれていたらその記事は v3 以前のものです。

設計

サブコマンドを 4 つ持つ形にします。 git や dotnet と同じ構造です。

コマンドやること
todo add "牛乳を買う" --priority high追加する
todo list [--all]一覧を出す
todo done 2終わった印を付ける
todo stats集計を出す

コード全体

読みどころ

enum でサブコマンドを表す

第 10 章の列挙型がそのまま効いています。 サブコマンドを足したら、match がコンパイルエラーになって気づけます。

derive で全部生成される

属性生成されるもの
#[derive(Parser)]引数の解析、--help、--version
#[derive(Subcommand)]サブコマンドの振り分け
#[derive(ValueEnum)]--priority high のような列挙型の値
#[derive(Serialize, Deserialize)]JSON との相互変換
System.Text.Json との比較

C# はリフレクションで実行時に型を調べます。 serde はコンパイル時にコードを生成します。 そのぶん速く、そして変換できない型はコンパイルエラーになります。

#[serde(rename_all = "lowercase")] のような属性で細かく制御できる点も、 C# の [JsonPropertyName] とよく似ています。

? でエラーが素直に流れる

main が Result を返すので、 ? で投げたエラーはそのまま利用者に表示されて、終了コードが 1 になります。

with_context で文脈を足す

これがあると、エラーが 「ファイルが見つかりません」だけでなく 「todo.json を読めませんでした: ファイルが見つかりません」 という形で出ます。利用者にとっての差は大きいです。

動かす

開発中は cargo run -- を使う

-- の後がプログラムへの引数になります。

--help は書いていないのに動きます。 clap が /// のコメントから自動生成しています。

リリースビルドと配布

dev（既定）release
最適化しないする
デバッグ情報付く付かない
ビルド時間短い長い
実行速度遅い（10 倍以上違うことも）速い
整数のあふれpanic する回り込む
出力先target\debug\target\release\
性能を測るときは必ず --release

「Rust なのに遅い」という話の大半は、デバッグビルドで測っています。 最適化なしのビルドは本当に遅いので、 比較するときは必ず --release を付けてください。

配布が圧倒的に楽

できあがった target\release\todo.exe はそれ 1 つで動きます。 .NET ランタイムのインストールも、自己完結型発行の設定も要りません。

C#Rust
実行に必要なもの.NET ランタイム（または自己完結型で同梱）その exe だけ
小さな CLI のサイズ自己完結型で 60 MB 前後数 MB
起動時間JIT のウォームアップがある即座
サイズをさらに削る

Cargo.toml に設定を足すと小さくなります。

panic = "abort" は panic をキャッチできなくなるので、 それで困らないツールだけに使ってください。

他の OS 向けに作る

Rust はクロスコンパイルができます。ターゲットを足すだけです。

ただしリンカが必要なので、そのままでは通らないことが多いです。 実務では GitHub Actions で各 OS 上でビルドするか、 cross というツール（Docker を使う）を使います。

自分の PC 向けだけなら、この心配は要りません。

配る方法
方法コマンド
exe を直接渡すtarget\release\todo.exe をコピー
crates.io に公開するcargo publish

やってみよう
  1. examples/21-cli-app で cargo run -- --help を実行して、自動生成されたヘルプを見てください。
  2. cargo run -- add "テスト" --priority low を実行し、todo.json が作られることを確認してください。
  3. cargo run -- done 99 を実行して、エラーメッセージと終了コードを確認してください（PowerShell では $LASTEXITCODE）。
  4. Command に Remove { id: u32 } を足して、match がエラーになることを確認してから実装してください。
  5. cargo build --release して、target\debug\ と target\release\ のファイルサイズを比べてください。

この章のまとめ

  • CLI の定番は clap（引数）＋ serde（JSON）＋ anyhow（エラー）。
  • サブコマンドは enum で表す。足すと match がエラーになって気づける。
  • clap は v4 で #[command] / #[arg] に変わった。#[clap(...)] は古い記事。
  • serde はコンパイル時にコードを生成する。リフレクションではない。
  • 性能を測るときは必ず --release。
  • できた exe は単体で動く。ランタイムの同梱が要らない。
