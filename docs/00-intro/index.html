はじめに — この教材の歩き方

Qt とは何か、なぜ PySide6 と Qt Widgets なのか、そして「ネットの記事どおりに書いたのに動かない」がなぜ起きるのかを先に片付けます。

この教材が解こうとしている問題

GUI プログラミングの入門でいちばん多い挫折は、文法が難しいことではありません。 「記事のとおりに書いたのに動かない」ことです。

Qt は 30 年近く使われてきた道具なので、Web 上には膨大な情報があります。 ところがその多くは Qt5 以前のもので、Qt6 ではそのまま書くと動きません。 初心者にとって最悪なのは、エラーメッセージを読んでも 「自分が間違えたのか、記事が古いのか」が判断できないことです。

やっかいなのは「エラーになるとは限らない」こと

たとえば from PySide6.QtWidgets import QAction は、Qt6 では はっきり ImportError になります。これはまだ親切なほうです。

一方で app.exec_()（末尾のアンダースコア）や Qt.AlignCenter（途中で切った書き方）は、 PySide6 では今も動いてしまいます。 古い書き方をそのまま受け付ける「寛容モード」があるためです。 動くので気づかないまま、時代遅れの書き方が身についてしまう。 こちらのほうが厄介です。

本文では、こうした箇所を見つけるたびにこの ⚠️ 印で名指しし、 「エラーになるのか、黙って動くのか」まで区別して書いていきます。

そこでこの教材は、書き方をひとつ決めました。 本文に載っているコードは、書き写したものではなく、実際に動かしたファイルそのものです。

  • コードは qt6-widgets/examples/ にある .py ファイルが唯一の原本です。ページを組み立てるときに、その中身をそのまま読み込んで表示しています。
  • スクリーンショットは、その同じファイルを実際に起動して撮影したものです。イラストでも作図でもありません。
  • ページを作るたびに全サンプルが自動で起動テストされ、1 つでもエラーになれば公開できない仕組みになっています。

つまり「本文とコードと画面写真が食い違う」ことが、構造的に起きません。 安心して、書いてあるとおりに手を動かしてください。

Qt とはなにか

Qt（キュート）は、デスクトップアプリの画面を作るための道具箱です。 もともと C++ 用に作られたもので、 KDE、VLC、OBS Studio、Autodesk Maya、Blender の一部など、 身の回りの多くのソフトが Qt で作られています。

その Qt を Python から使えるようにしたものが PySide6（別名 Qt for Python）です。 Qt を開発している会社が自ら公式に提供しているので、 Qt 本体の新しいバージョンにもきちんと追随します。

Qt Widgets と Qt Quick — この教材が選んだほう

Qt には、系統のまったく違う UI の作り方が 2 つあります。 最初にここで迷う人が多いので、先に整理しておきます。

Qt Widgets（この教材）Qt Quick / QML
書く言語 Python だけ Python ＋ QML という別言語
得意なこと ボタン・表・メニューが並ぶ業務アプリ、ツール類 アニメーション、タッチ操作、独自デザインの画面
見た目 OS のネイティブな見た目になる 自分でデザインする（どの OS でも同じ）
向いている先 デスクトップ 組み込み機器、モバイル、デスクトップ
最初の一歩 短い。Python の知識だけで始められる QML の文法を覚えるところから

この教材は Qt Widgets だけを扱います。 理由は単純で、Python を知っている人が「動くデスクトップアプリ」に最短でたどり着けるからです。 表やメニューやダイアログといった、業務ツールに必要なものが最初から全部そろっています。

ヒント

Qt Widgets が「古い技術」ということはありません。 最新の Qt 6.11 でも現役で保守されており、デスクトップ向けアプリの主力です。 アニメーションの多い凝った画面を作りたくなったときに、Qt Quick を学べば十分です。

LTS って何？ 6.8 のほうがいいの？

Qt には 4 つおきに LTS（長期サポート）版があり、現在は 6.8 系がそれにあたります。 企業が何年も保守する製品なら LTS を選ぶ意味がありますが、 学習や個人の道具づくりなら最新版で問題ありません。 この教材の内容は 6.8 でもほぼそのまま通用します。
