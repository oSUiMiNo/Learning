Rust の準備は rustup を入れる、これだけです。 コンパイラ・パッケージ管理・整形・静的解析が全部まとめて付いてきます。

ただし Windows にはもう 1 つ必要なものがあります。 ここを知らずに進めると、最初の cargo run で 「リンカが見つからない」と言われて止まります。先に片付けておきましょう。

必要なもの

要るもの条件
OSWindows 11（10 でも同じ手順で動きます）
rustupこれを入れると Rust 本体が付いてくる
Microsoft C++ ビルドツールWindows では必須。インストーラが案内してくれる
エディタVS Code を推奨（第 2 章で設定します）
ディスク3 GB 程度。ビルドツールが大きい
なぜ C++ の道具が要るのか

.NET は自前のランタイムとリンカを持っているので、SDK 1 つで完結します。 Rust はネイティブの実行ファイルを直接吐くため、 最後に「オブジェクトファイルをつないで .exe にする」工程が必要です。 Windows では、この工程を担う link.exe と Windows API のライブラリが Visual Studio 側に入っています。

Rust がそれを同梱しないのは、Microsoft のライセンス上、再配布できないからです。 そのため「Microsoft の道具を自分で入れてもらう」形になっています。

rustup を入れる

rustup.rs を開くと、 Windows なら rustup-init.exe のダウンロードリンクが出ます。 これを実行します。

winget でも入れられます

コマンドで済ませたい場合は、PowerShell で次のように打っても入ります。 入るものは同じで、この後の画面もほぼ同じように出ます。

winget install Rustlang.Rustup

rustup-init.exe を実行すると、黒い画面が開いてこう出ます。

見るべきところは Current installation options: の 4 行です。

項目既定値意味
default host triplex86_64-pc-windows-msvc作る実行ファイルの種類。これでよい
default toolchainstable安定版。学習でも実務でもこれ
profiledefaultコンパイラ＋ドキュメント＋clippy＋rustfmt
modify PATH variableyesコマンドがどこからでも打てるようになる

全部そのままでよいので、1 を選ぶか、そのまま Enter を押します。

ARM 版の Windows を使っている場合

Snapdragon などの ARM 機では aarch64-pc-windows-msvc と出ます。 それが正しいので、そのまま進めてください。 この教材の内容はどちらでも変わりません。

C++ ビルドツールが無いときの画面

Visual Studio を入れたことがない環境では、 先へ進む前にこの画面が出ます。ここが Windows 固有の関門です。

1 を選んでください。 rustup が Visual Studio Community のインストーラを起動して、必要な部品だけ入れてくれます。 数 GB のダウンロードがあるので、ここは時間がかかります。

古い記事では「手動で入れろ」と書かれています

以前の rustup にはこの自動インストールがなく、 「先に Visual Studio を入れてから rustup を実行せよ」という手順が一般的でした。 そのため、そう書いてある記事が今もたくさんあります。

いまは rustup が面倒を見てくれるので、先に何も入れなくて大丈夫です。 もし手動で入れたい場合は 2 を選び、 Visual Studio Installer で 「C++ によるデスクトップ開発」にチェックを入れます。

3（入れない）は、GNU ABI を狙うと分かっている人向けです。 初心者は選ばないでください。後で必ず詰まります。

すべて終わると、こう出ます。

ターミナルを開き直すこと

完了画面にも書いてありますが、いま開いているターミナルでは cargo がまだ使えません。 PATH の変更は、新しく開いたターミナルにしか反映されないためです。

「入れたのに cargo は認識されていません と言われる」の原因は、 ほぼこれです。PowerShell を閉じて開き直してください。

ちゃんと入ったか確かめる

新しく PowerShell を開いて、3 つ打ちます。

版の番号は読んでいる時期によって違って当然です。 大事なのは3 つとも答えが返ってくることです。

いま入っているものの全体像は rustup show で見られます。

更新とアンインストール

Rust は 6 週間ごとに新しい版が出ます。上げるのは 1 行です。

rustup update

やめたくなったときも 1 行で、入れたものが全部消えます。 レジストリの PATH も元に戻ります。

rustup self uninstall

Windows でつまずきやすいところ

「link.exe が見つかりません」と言われたら

次のようなエラーで cargo build が止まる場合、 C++ ビルドツールが入っていません。

error: linker `link.exe` not found | = note: program not found note: the msvc targets depend on the msvc linker but `link.exe` was not found note: please ensure that Visual Studio 2017 or later, or Build Tools for Visual Studio were installed with the Visual C++ option.

メッセージの言うとおり、Visual Studio Installer で 「C++ によるデスクトップ開発」を追加すれば直ります。 rustup-init.exe をもう一度実行して 1 を選ぶのでも構いません。

ビルドが妙に遅いとき

Rust のビルドは大量の小さいファイルを target フォルダに書きます。 Windows Defender のリアルタイム保護がそれを 1 つずつ検査するので、 体感で 2〜3 倍遅くなることがあります。

気になる場合は、Windows セキュリティの 「ウイルスと脅威の防止」→「除外の追加」で、 作業フォルダと %USERPROFILE%\.cargo を除外に入れると改善します。 （業務の端末では、社内の方針を確認してから行ってください。）

target フォルダが大きくなる

target には中間生成物が全部入るので、 小さなプロジェクトでも数百 MB、依存が多いと数 GB になります。 消しても困りません。次のビルドで作り直されるだけです。

cargo clean

target は Git に入れないのが決まりです。 cargo new は .gitignore を自動で用意してくれます。

日本語のパスとパスの長さ

作業フォルダのパスに日本語や空白が入っていても、いまの Rust は動きます。 ただし依存が深いプロジェクトでは、Windows のパス長制限（260 文字）に当たることがあります。 C:\rust\ のような短い場所に置いておくと安心です。 この教材のターミナル画面も C:\rust\ を前提にしています。

やってみよう
  1. rustc --version の出力を、このページ上部のバッジと見比べてください。一致していれば理想的です。
  2. rustup show を打って、host が x86_64-pc-windows-msvc（ARM 機なら aarch64-...）になっていることを確認してください。
  3. rustup doc と打ってみてください。ネットに繋がっていなくても読める公式ドキュメントがブラウザで開きます。

この章のまとめ

  • 準備は rustup を入れるだけ。コンパイラ・cargo・clippy・rustfmt がまとめて入る。
  • Windows は C++ ビルドツールが別途必要。いまは rustup が自動で入れてくれる（選択肢の 1）。
  • インストール後はターミナルを開き直す。「cargo が無い」の原因はほぼこれ。
  • link.exe not found は C++ ビルドツール不足の合図。
  • 更新は rustup update、削除は rustup self uninstall。
  • target は消してよい生成物。Git には入れない。
