2 番目のエラーがなぜ厄介なのか

use rand::Rng; と書いているのに 「random_range というメソッドはありません」と言われます。 import は成功しているのにメソッドが無いので、意味が分かりません。

答えはこうです。rand 0.10 で 便利なメソッド群が Rng から RngExt へ移りました。 Rng という名前のトレイト自体は今も存在するので、 use は通ってしまうのです。

直し方は use rand::RngExt; にするか、 use rand::prelude::*; でまとめて持ってくるかです。

use rand::Rng; let secret = rand::rng().random_range(1..=100);
use rand::RngExt; let secret = rand::rng().random_range(1..=100);
動く数当てゲーム

正しい書き方で書いたものが examples/99-guessing にあります。 自動で当てにいく形にしてありますが、構造は定番のものと同じです。

人が遊ぶ形にするには、guess を作っている行を 標準入力の読み取りに差し替えます。

use std::io::{self, Write}; let mut input = String::new(); print!("入力してください: "); io::stdout().flush().unwrap(); io::stdin().read_line(&mut input).unwrap(); let guess: u32 = match input.trim().parse() { Ok(n) => n, Err(_) => { println!("数字を入れてください"); continue; } };

flush() が必要なのは、print!（改行なし）が すぐには画面に出ないためです。これは C# の Console.Write と違う点なので、忘れると 「プロンプトが出ないまま入力待ちになる」という現象になります。

記事の古さを見抜く手がかり

記事に日付が書いていないことはよくあります。次のものが目印になります。

  • extern crate がある → 2018 年より前
  • println!("{}", x) ばかり → 2021 年より前の可能性
  • try!(..) がある → かなり古い（2016 年ごろ）
  • rand::thread_rng() → rand 0.8 以前
  • #[clap(...)] → clap v3 以前
  • 「Rust 拡張を入れる」→ 2022 年より前
  • edition = "2018" と書いてある → そのまま動くが、記事は古い

そして最強の判定方法は、とりあえず手元でコンパイルしてみることです。 Rust のエラーメッセージは直し方まで書いてくれるので、 古い書き方は自力で直せることが多いです。

この先にあるもの

本書では扱わなかった領域を、入口だけ紹介します。

unsafe

unsafe { // 生ポインタの参照外し、C の関数呼び出しなど }
unsafe は「検査を切る」ではない

unsafe でできるようになるのは 5 つだけです。 生ポインタの参照外し、unsafe 関数の呼び出し、 可変な static の読み書き、unsafe トレイトの実装、 共用体のフィールドアクセス。

所有権と借用の検査は unsafe の中でも働いています。 「面倒だから unsafe で回避する」ということはできません。

アプリを書くうえでは、まず必要になりません。 2024 エディションでは unsafe fn の中でも unsafe ブロックを書くことが求められるようになり、 より厳しくなっています。

既存の C# 資産と組み合わせる

「重い処理だけ Rust に置き換える」という使い方ができます。 Rust 側を crate-type = ["cdylib"] でビルドして DLL を作り、 C# から [DllImport] で呼びます。

[lib] crate-type = ["cdylib"]

現実的で効果の出やすい導入経路です。 全部を書き換えなくても、Rust の速さと安全性を部分的に得られます。

Rustlings をやってみる

所有権と借用は、読むだけでは身につきません。 公式の練習問題集をやると効率よく慣れられます。

cargo install rustlings rustlings init cd rustlings rustlings

コンパイルエラーを直していく形式で、 本書の第 6・7・15 章の内容がそのまま演習になります。

おわりに

Rust が「難しい」と言われる理由は、第 0 章で書いたとおりです。 C# なら実行時に分かっていた不具合が、コンパイル時に前倒しで出てくる。 最初にまとめて来るので重く感じますが、総量は減っています。

そして借用検査と戦っている時間は、無駄ではありません。 それは本番で落ちるはずだったコードを、手元で直している時間です。

詰まったときは、この 3 つを思い出してください。

  • エラーメッセージを最後まで読む。Rust は直し方まで書いてくれます。
  • とりあえず clone() して前に進む。動かないコードより、少し遅いコードのほうがましです。
  • 手元でコンパイルして確かめる。記事が古いのか自分が間違えたのかは、それでしか分かりません。
