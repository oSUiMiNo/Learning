Rust の売り文句のひとつが「恐れなき並行性（fearless concurrency）」です。

中身を見ると、新しい仕組みはほとんどありません。 所有権と借用の規則を、そのままスレッドに適用しただけです。 第 6 章と第 7 章が分かっていれば、この章は驚くほど素直に読めます。

何が守られているのか

トレイト意味
Sendその型の値を、別のスレッドへ移してよい
Syncその型への参照を、複数のスレッドから同時に持ってよい
C# との決定的な違い

C# には「この型はスレッド安全か」を表す型がありません。 ドキュメントに「このクラスはスレッドセーフではありません」と書いてあるだけで、 破ってもコンパイルは通ります。

var list = new List<int>(); Parallel.For(0, 1000, i => list.Add(i)); // データ競合

Rust で同じことを書こうとすると、コンパイルエラーになります。 Vec への &mut を複数のスレッドに渡せないからです。

データ競合が、実行時のバグではなく型の不一致として現れる ── これが「恐れなき並行性」の意味です。

スレッドを起こす

let handle = thread::spawn(move || { // 別のスレッドで動く format!("完了") }); let result = handle.join().unwrap(); // 終わるのを待って戻り値を受け取る
move が必要な理由

thread::spawn に渡すクロージャには、たいてい move が必要です。

新しいスレッドは、この関数より長く生きるかもしれません。 そのとき借用していた値がもう無いと困るので、 所有権をもらう（move）ことが要求されます。

closure may outlive the current function と言われたら move を足してください。

thread::spawn は OS のスレッドを直接起こします。 C# の Task.Run のようなスレッドプールは標準にありません。 軽い並行処理をたくさん回したいときは、第 20 章の async を使います。

チャネルで値を渡す

let (tx, rx) = mpsc::channel(); for id in 1..=3 { let tx = tx.clone(); // 送信側は複製できる thread::spawn(move || { tx.send(format!("仕事 {id} の結果")).unwrap(); }); } drop(tx); // 元の送信側を落とす let received: Vec<String> = rx.iter().collect();
mpsc = multi producer, single consumer

送る側は何個でも作れて（clone）、受ける側は 1 つだけです。 send すると値の所有権も一緒に移ります。 だから「送ったのに元のスレッドでも触ってしまう」ことが起きません。

drop(tx) を忘れると止まらない

rx.iter() は「送信側が全部消えるまで」待ちます。 元の tx を落とさないと、それが永遠に生きているので プログラムが終わりません。

複製した tx をスレッドに渡したら、元の tx は drop(tx) で明示的に落としてください。

Mutex — 共有して書き換える

let counter = Arc::new(Mutex::new(0)); for _ in 0..8 { let counter = Arc::clone(&counter); handles.push(thread::spawn(move || { for _ in 0..1000 { let mut value = counter.lock().unwrap(); *value += 1; } // ここでロックが自動的に外れる })); }
lock 文より安全

C# の lock (obj) { } は、 どのオブジェクトが何を守っているのかコードから読めません。 lock し忘れてもコンパイルは通ります。

Rust の Mutex<T> は守る対象を内側に持ちます。 中身に触るには lock() を通るしかないので、 ロックし忘れが起こりえません。

C# の lockRust の Mutex<T>
守る対象慣習で決める型に含まれる
ロック忘れ起こりうる起こりえない
解放忘れlock 文なら起きない起きない（Drop）
読み書きの区別無い（ReaderWriterLock は別物）RwLock がある
lock() が Result を返す理由

ロックを持っていたスレッドが panic すると、 そのロックは「毒された（poisoned）」状態になります。 守っていたデータが中途半端な状態かもしれないからです。

学習中は .unwrap() で構いません。 「他のスレッドが落ちたならこちらも落ちてよい」という判断です。

数を数えるだけなら Atomic

let hits = Arc::new(AtomicUsize::new(0)); hits.fetch_add(1, Ordering::Relaxed);

Mutex よりずっと軽いので、カウンタやフラグにはこちらを使います。 C# の Interlocked に相当します。

Ordering は何を指定しているのか

メモリの読み書きが、他のスレッドから見てどの順番に見えるかを指定します。

指定使う場面
Relaxed単に数えるだけ。ふだんはこれ
SeqCstいちばん厳しい。迷ったらこれで安全
Acquire / Release他のデータとの前後関係を保証したいとき

C# の Interlocked は常に最も厳しい順序になります。 Rust は選べるので速くできますが、 分からないうちは SeqCst にしておけば間違いません。

スコープ付きスレッド — 借用できる

thread::scope の中のスレッドは、 抜ける前に必ず終わることが保証されます。 だから外側の値を Arc に包まずに借用できます。

let data = [1, 2, 3, 4, 5, 6]; let (left, right) = data.split_at(3); let total = thread::scope(|s| { let a = s.spawn(|| left.iter().sum::<i32>()); let b = s.spawn(|| right.iter().sum::<i32>()); a.join().unwrap() + b.join().unwrap() });
scope は比較的新しい

thread::scope が標準に入ったのは Rust 1.63（2022 年）です。 それより前は crossbeam クレートを使う必要がありました。

古い記事で「スレッドに借用を渡すには crossbeam が必要」と書かれていたら、 いまは標準で足りると読み替えてください。

Rc は渡せない

Rc をスレッドに渡すとコンパイルエラー

Rc はカウントの増減をアトミックに行わないので、 複数のスレッドから触ると壊れます。 そのため Rc は Send でも Sync でもありません。

渡そうとすると `Rc<...>` cannot be sent between threads safely と言われます。Arc に置き換えれば直ります。

単一スレッド複数スレッド
Rc<T>Arc<T>
RefCell<T>Mutex<T> / RwLock<T>
Rc<RefCell<T>>Arc<Mutex<T>>

Arc のほうが少し遅いので、 スレッドをまたがないなら Rc を選ぶのが正しい判断です。 「とりあえず Arc」ではなく、必要に応じて選びます。

並列処理を楽にするクレート

rayon

データ並列処理をしたいなら rayon が定番です。 イテレータの iter() を par_iter() に変えるだけで並列になります。

use rayon::prelude::*; let total: u64 = numbers.par_iter().map(|n| heavy(*n)).sum();

C# の AsParallel()（PLINQ）とまったく同じ発想です。 しかも所有権の規則があるので、 並列にして安全でないコードはコンパイルが通りません。

全体を動かす

やってみよう
  1. examples/19-concurrency を動かして、カウントが 8000 になることを確認してください。
  2. Arc::new(Mutex::new(0)) を Rc::new(RefCell::new(0)) に変えて、コンパイルエラーになることを確認してください。これがこの章の要点です。
  3. thread::spawn(move || ...) の move を消して、どんなエラーになるか見てください。
  4. drop(tx) を消して実行し、プログラムが終わらなくなることを確認してください（Ctrl + C で止めてください）。

この章のまとめ

  • 並行処理に新しい規則は無い。所有権と借用をスレッドに適用しただけ。
  • Send（移せる）と Sync（共有できる）が型として表されている。
  • Rc はスレッドに渡せない。Arc に置き換える。
  • Mutex<T> は守る対象を内側に持つので、ロック忘れが起こりえない。
  • スレッドに渡すクロージャには move が必要。
  • カウンタは Atomic、データ並列は rayon（＝PLINQ）。
  • thread::scope なら借用をスレッドに渡せる（Rust 1.63 以降）。
