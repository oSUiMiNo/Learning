'a という記法は、Rust でいちばん怖がられているものです。 けれど正体は単純です。

「この参照はいつまで有効か」をコンパイラに伝えるだけの注釈です。 新しい寿命を作るのではなく、すでにある寿命に名前を付けているだけ。 それが分かれば、あとは短い話です。

何を防いでいるのか

実際にはみ出させてみると、こう言われます。

C# ではこれが起きない理由

C# で同じことを書いても問題ありません。 GC が「まだ誰かが参照している」ことを知っているので、 オブジェクトは生き続けます。

Rust には GC が無いので、inner はブロックを抜けた時点で片付けられます。 その後に outer を使えば、片付けた場所を読むことになります。 C や C++ ならダングリングポインタで、 運が良ければ動き、運が悪いとおかしな値を読んだり落ちたりします。

ライフタイムは、それをコンパイル時に止めるための仕組みです。

ほとんどの場合、書かなくてよい

先に安心する話をします。ライフタイムはほとんど書かなくて済みます。 コンパイラが推測できる場合は省略できて、その規則（省略規則）が実用上ほぼ全部を覆います。

fn first_word(text: &str) -> &str { text.split_whitespace().next().unwrap_or("") }
省略規則（3 つ）
  1. 引数の各参照には、それぞれ別のライフタイムが割り当てられる。
  2. 引数の参照が 1 つだけなら、戻り値のライフタイムはそれになる。
  3. メソッドで &self があるなら、戻り値のライフタイムは &self のものになる。

実務のコードは大半がこの 2 番目か 3 番目に当てはまります。 だから 'a を書く場面は意外に少ないのです。

書かされる場面

規則に当てはまらないのは、参照の引数が 2 つ以上あって、参照を返すときです。

コンパイラの提案どおりに書けば通ります。

fn longer<'a>(a: &'a str, b: &'a str) -> &'a str { if a.chars().count() >= b.chars().count() { a } else { b } }
この 'a が言っていること

「a と b と戻り値は、同じくらい生きる」 ── もっと正確に言えば 「戻り値は、a と b のうち短いほうが生きている間だけ有効」 です。

これを書くことで、呼び出し側では次のような使い方が止められます。

let long = String::from("うさぎとかめ"); let result; { let short = String::from("かめ"); result = longer(&long, &short); } println!("{result}");
'a は「長さ」を指定するものではない

よくある誤解です。'a と書くことで参照が長生きするようになる、 ということはありません。

'a は「これらの寿命には関係がある」と宣言しているだけで、 実際の寿命は変わりません。 コンパイラはその宣言と実際の寿命を突き合わせて、矛盾があれば怒ります。

だから「エラーが出たから 'a を足す」では直りません。 直すのは寿命そのもの（もっと外側で値を作る、所有させる）です。

構造体に参照を持たせる

構造体が参照を持つなら、ライフタイムが必須になります。

struct Excerpt<'a> { source: &'a str, part: &'a str, } impl<'a> Excerpt<'a> { fn new(source: &'a str) -> Self { /* ... */ } fn part(&self) -> &str { self.part } // 省略規則 3 で書かなくてよい }

これは「この構造体は、借りている元より長生きできない」という宣言です。

迷ったら「所有させる」

ライフタイムで詰まったときのいちばん実用的な逃げ道がこれです。 参照をやめて、所有する型にしてしまいます。

struct Excerpt<'a> { part: &'a str, }
struct Excerpt { part: String, }

String にすれば 'a が消えます。 .to_string() のコストを払うだけです。

初心者のうちは、構造体のフィールドは String にしておくことを勧めます。 参照を持たせるのは、性能が本当に問題になってからで構いません。 第 8 章で「構造体のフィールドは String」と書いたのはこの理由です。

'static

fn motto() -> &'static str { "速く、安全に" }

'static は「プログラムが終わるまで生きる」という意味です。 文字列リテラルは実行ファイルに埋め込まれているので、これになります。

'static を安易に付けないこと

エラーを消すために 'static を付けたくなることがありますが、 それは「この値は永遠に生きます」という強い主張です。 ふつうのローカル変数には当てはまらないので、たいてい別のエラーに変わるだけです。

&'static str が正しいのは、文字列リテラルや const／static で定義したものを返すときだけです。

全体を動かす

ライフタイムのエラーで詰まったときの手順
  1. コンパイラの提案をそのまま書く。E0106 なら書き方の例が出ている。
  2. 値を作る場所を外側に移す。ブロックの外で let する。
  3. 参照をやめて所有させる。&str → String、&[T] → Vec<T>。
  4. それでも駄目なら設計を見直す。参照を持つ構造体をやめる、第 18 章の Rc を使う。

2 番目と 3 番目でほぼ解決します。 'a を増やして解決しようとすると、たいてい迷路に入ります。

この章のまとめ

  • 'a は「参照が有効な区間」に名前を付けるだけ。寿命を伸ばす機能ではない。
  • 省略規則があるので、実際に書く場面は少ない。
  • 書かされるのは「参照の引数が 2 つ以上あって、参照を返すとき」。
  • 参照を持つ構造体には必須。ただしString にすれば悩まなくて済む。
  • 詰まったら「外側で作る → 所有させる」の順に試す。'a を増やしても直らない。
  • 'static はリテラルや定数を返すときだけ。安易に付けない。
