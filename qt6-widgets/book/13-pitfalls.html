PyQt6 と PySide6 の違い

検索すると PyQt6 の記事も大量に出てきます。 この 2 つはほぼ同じもので、同じ Qt を別の会社が Python から使えるようにしたものです。

PyQt6 の記事を PySide6 に読み替える

PyQt6 → PySide6、pyqtSignal → Signal、 pyqtSlot → Slot。この 3 つを置き換えるだけで、たいてい動きます。

ライセンス面では、クローズドソースのソフトを配布する予定があるなら LGPL の PySide6 のほうが扱いやすいです（GPL は原則ソース公開が必要）。

アプリが固まるとき — 重い処理の扱い

第 2 章のイベントループの図で触れた話です。 スロットの中で時間のかかる処理をすると、その間 UI は完全に止まります。

def on_clicked(self): result = download_large_file() # 10 秒かかる self.label.setText(result)

解決策は主に 3 つあります。

方法向いている場面
QThread / QThreadPool ＋ QRunnable CPU を使う処理、既存の同期的なライブラリを呼ぶとき
QProcess 外部コマンドを実行するとき
QtAsyncio（PySide6 に同梱） Python の asyncio と組み合わせたいとき
別スレッドから画面を触ってはいけない

Qt では、ウィジェットの操作はすべてメインスレッドから行う決まりです。 別スレッドから label.setText() を呼ぶと、動くこともありますが、 いずれ不定期にクラッシュします。 結果はシグナルで送り、メインスレッド側のスロットで画面を更新してください。 シグナルはスレッドをまたいでも安全に届きます。

配布する

Python が入っていない人に渡すには、実行ファイルにまとめます。 定番は PyInstaller です。

pip install pyinstaller pyinstaller --noconfirm --windowed --name "MyApp" ch12_todo_app.py
オプション意味
--windowed実行時に黒いコンソール窓を出さない（GUI アプリでは必須）
--onefile1 つの exe にまとめる。起動は遅くなる
--icon=app.icoアイコンを指定する
配布でつまずきやすい点
  • クロスコンパイルはできない。Windows 版は Windows で、macOS 版は macOS でビルドする必要があります
  • ファイルサイズは大きい。Qt を丸ごと含むので数十〜百数十 MB になります
  • 相対パスが変わる。画像などを読む場合、sys._MEIPASS を見る必要があります
  • macOS では署名と公証をしないと「開発元を確認できません」と警告が出ます

公式ドキュメントの歩き方

最終的にいちばん頼りになるのは公式のリファレンスです。読むコツがあります。

  • C++ 版のドキュメントを読む。 doc.qt.io/qt-6 のほうが情報量が多く、更新も早いです。 QWidget::setEnabled() は Python では widget.setEnabled()、と読み替えるだけです
  • Python 版は doc.qt.io/qtforpython-6。 Python 特有の書き方（戻り値がタプルになる、など）はこちらで確認します
  • クラスのページでは、まず「Signals」の節を探す。 そのウィジェットで何ができるかは、シグナルの一覧を見るのがいちばん早いです
  • 継承元もたどる。 QPushButton のページに載っていないメソッドは、 QAbstractButton や QWidget のページにあります
