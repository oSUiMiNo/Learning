## 1. この教材で「実物」をどう捕まえたか

共通ルールの 1 節が言う「この分野で実物とは何か」への、この教材なりの答えです。

**GUI 教材の実物は画面です。** だから次の形にしました。

```
examples/*.py  ←── 本文がビルド時に読み込む（書き写さない）
      │
      └────────→ Xvfb 上で実際に起動 → スクリーンショット → 本文に載る
```

同じファイルが「本文のコード」と「画面写真の出どころ」を兼ねるので、
両者が食い違うことが原理的に起きません。

加えて、本文が主張する Qt5 → Qt6 の挙動差は `tools/check_claims.py` で
実物の PySide6 に対して実行して確かめています（→ 2-1）。

| ツール | 何を担保しているか |
|---|---|
| `tools/check_examples.py` | 全サンプルが画面なしで起動し、例外も警告も出さずに終わる |
| `tools/check_claims.py` | 本文が書いている「Qt5 ではこう、Qt6 ではこう」が事実である |
| `tools/shots.py` | 画面写真が、本文のコードを実際に動かしたものである |
| `tools/shots_cpp.py` | 付録の C++ サンプルが実際にビルドでき、同じ画面を出す |
| `tools/build.py` | 未解決の指示子・壊れたリンク・欠落画像がない |
| `tools/preview.py` | 表示崩れがなく、掲載コードが実ファイルと 1 バイトも違わない |

## 2. やらかした間違い

### 2-1. Web の記事を信じて書いた早見表が、5 行間違っていた

第 13 章に「Qt5 の書き方は Qt6 ではこうエラーになる」という表を作りました。
複数の解説記事を読んで書いたので、自信もありました。

実物で試したら、**5 行が間違っていました。**

| 書いたこと | 実際 |
|---|---|
| `app.exec_()` は `AttributeError` | 動く（`DeprecationWarning` は出る） |
| `Qt.AlignCenter` は `AttributeError` | **動く。警告すら出ない** |
| `Qt.Horizontal` / `Qt.Checked` は `AttributeError` | 動く |
| `QMessageBox.Yes` は `AttributeError` | 動く（`==` 比較も成立する） |

原因は、**PyQt6 の挙動を PySide6 の話として書いていた**ことです。
Qt には Python バインディングが 2 つあり、
PySide6 は古い書き方を黙って受け付ける「寛容モード」を持ち、PyQt6 は持ちません。
検索で出てくる記事は両者が混ざっているのに、どちらの話か明示しないことが多い。

対処として `tools/check_claims.py` を書き、早見表の各行を実物に対して実行するようにしました。

```python
expect("QAction は QtWidgets から消え、QtGui にある",
       not hasattr(QtWidgets, "QAction") and QtGui.QAction is QAction)
expect("Qt.AlignCenter は使えて、完全修飾版と等しい",
       Qt.AlignCenter == Qt.AlignmentFlag.AlignCenter)
expect("Qt.AlignCenter は警告を出さない", not caught)
```

> Qt で教材を書くなら、**PySide6 と PyQt6 のどちらの話かを常に意識してください。**
> API はほぼ同じですが、この enum の厳格さのように**挙動が割れる箇所があります**。
> そして記事の側はそれを明示してくれません。

### 2-2. 対応 Python バージョンを想像で書いた

「Python 3.9 以上」と書いていましたが、PySide6 6.11 の実際は **3.10 以上 3.14 以下**でした。
3.9 の読者は第 1 章の `pip install` で失敗します。

```python
import importlib.metadata as md
md.metadata("PySide6").get("Requires-Python")   # '<3.15,>=3.10'
```

訂正のついでに、失敗したときのエラー文面も本文に載せました。
「パッケージ名を間違えたのかな」と思いがちですが、実際は Python のバージョンが原因、という話です。

### 2-3. モデル/ビューの「おまじない」が、実は不要だった

第 10・12 章で次のように書いていました。どちらも**現行バージョンでは不要**でした。

- `TextAlignmentRole` は `int(...)` で包んで返すこと
- `CheckStateRole` は `.value` を付けて返すこと

両方の書き方でウィジェットを描画させ、**画像のハッシュを比較して同一**であることを確認しました。
初期の PySide6 で列挙型の扱いが不安定だった頃の慣習が、記事に残り続けていたものです。

### 2-4. 逆に、実測でしか見つからない本物の罠が出てきた

上を検証している最中に見つかったものです。

`data()` からは列挙型をそのまま返してよい。ところが `setData()` に**渡ってくる**値は
列挙型ではなく `int` です。したがって次のコードは、
**エラーも警告も出さずに、ただ動きません**（チェックしても完了にならない）。

```python
self._items[index.row()]["done"] = (value == Qt.CheckState.Checked)   # 常に False
```

`2 == Qt.CheckState.Checked` が `False` であることを確認して、症状として本文に書きました。
モデル/ビューを扱うなら、**返す側と受け取る側を両方触ってみてください。**

## 3. 撮影まわりで詰まった点

### 3-1. 撮影ハーネスはサンプルの「外」に置く（Qt での具体形）

共通ルール 3-1 の Qt 版です。`QApplication.exec` を差し替えます。

```python
# tools/_capture.py — サンプルは自分が撮影されていることを知らない
original_exec = QApplication.exec

def patched_exec():
    QTimer.singleShot(delay, capture)     # 描画が落ち着いた頃に撮る
    return original_exec()

QApplication.exec = staticmethod(patched_exec)
runpy.run_path(str(script), run_name="__main__")
```

### 3-2. `QApplication.exec` は静的メソッド

上を `patched_exec(self)` と書いて
`TypeError: exec() takes no arguments (1 given)` に遭いました。
`staticmethod` で包む必要があります。差し替える前に、静的かどうかを確認してください。

### 3-3. モーダルダイアログを撮ろうとすると固まる

「ボタンを押す → 少し待つ → 撮る」と直列に繋いだところ、撮影までたどり着きませんでした。
**モーダルダイアログを開くボタンの `click()` は、ダイアログが閉じるまで戻ってこない**からです。

解決は、**操作を絶対時刻で予約する**ことでした。

```python
at = settle
for step in steps:
    QTimer.singleShot(at, make_action(step))   # 直列に繋がず、それぞれ独立に予約
    at += step.get("ms", 250)
QTimer.singleShot(at + 250, capture)           # 撮影も独立に予約
```

タイマーは入れ子のイベントループの中でも発火するので、これで動きます。

さらに、**モーダルが開いていると `quit()` では終われません。**

```python
for window in visible_windows():
    window.close()          # 入れ子のイベントループを先に畳む
QApplication.instance().quit()
```

### 3-4. 複数ウィンドウを撮ると、背景の黒が写り込む

ダイアログと親ウィンドウを一緒に撮るため画面全体を取り込んだところ、
Xvfb の黒い背景が額縁のように写りました。

解決は、**画面を撮るのをやめて、各ウィンドウを個別に取り込み、自前で並べ直す**ことでした。

```python
modal = QApplication.activeModalWidget()
ordered = [w for w in windows if w is not modal] + [w for w in windows if w is modal]

canvas.fill(QColor("#cdc9c2"))            # 中立的な下地を自分で用意する
for offset, pixmap in shots:              # 手前に来るべきものを最後に描く
    painter.drawPixmap(offset, pixmap)
```

`topLevelWidgets()` は重なり順を返さないので、
`activeModalWidget()` で「手前に来るべきもの」を決めています。

### 3-5. 2 倍解像度は「どちらの座標系か」を間違えやすい

`QT_SCALE_FACTOR=2` で撮るとき、切り出し範囲に
**すでに倍率がかかった値**を渡してしまい、余白だらけの画像ができました。

`grabWindow()` が受け取るのは**拡大前の座標**で、返る画像が拡大後の画素数になります。
**倍率を二重にかけない。**

### 3-6. 保存機能のあるサンプルは、撮るたびに違う画面になる

第 12 章の ToDo アプリが前回の実行結果を読み込んでいました。

```python
env["XDG_DATA_HOME"] = str(throwaway_dir)   # 撮影ごとに使い捨て
```

`QStandardPaths` の参照先を環境変数で差し替えられるのは、この用途で便利です。

### 3-7. `runpy.run_path` は import パスを通してくれない

隣のサンプルを import するサンプル（`ch10_filter.py` が `ch10_tableview` を使う）が
`ModuleNotFoundError` で落ちました。
**直接 `python foo.py` では動くのにハーネス経由だと動かない**、という分かりにくい形で出ます。

```python
sys.path.insert(0, str(script.parent))   # 直接実行したときと同じ状態にする
```

### 3-8. サンプル同士を import させるなら、実行部をガードする

上を直したら、今度は import した側のアプリまで起動しました。
モジュール直下に実行コードを置いていたからです。

```python
if __name__ == "__main__":     # import されたときは動かさない
    app = QApplication(sys.argv)
    ...
```

これは教材としても良い題材になり、第 10 章で説明する機会になりました。

### 3-9. ウィンドウ枠は CSS で描く

スクリーンショットにタイトルバーを合成しようとしてやめ、HTML/CSS 側で描いています。
撮影時に「実際のウィンドウタイトルとサイズ」だけを `docs/qt6-widgets/img/shots.json` に
書き出し、`build.py` が読んで枠を組み立てます。

```python
meta = {
    "title": windows[0].windowTitle(),
    "css_width": round(pixmap.width() / ratio),
    "css_height": round(pixmap.height() / ratio),
}
```

### 3-10. C++ のサンプルは別の撮り方が要る

付録の C++ 章では `QApplication.exec` を差し替える手が使えません（自前のプロセスなので）。
**同じ仮想ディスプレイ上でアプリと取り込み役を同居させて**解決しました。

```
Xvfb 起動 → C++ バイナリを背景で実行 → 少し待つ
         → PySide6 のスクリプトで画面を切り出す → バイナリを終了
```

ウィンドウマネージャがいないためウィンドウは必ず原点に出るので、
切り出し位置は決め打ちできます。**制約が逆に有利に働いた例です。**

## 4. Qt / PySide6 の環境まわり

| 症状 | 原因と対処 |
|---|---|
| `ImportError: libEGL.so.1` | OS 側の共有ライブラリ不足。`apt-get update` してから `libegl1 libxkbcommon-x11-0 libxcb-*` を入れる（update を飛ばすと 404 で失敗する） |
| Linux で `xcb` プラグインが読めない | 同上。第 1 章にも同じ内容を書いてある |
| 日本語が豆腐になる | フォントの有無を先に確認する（`fc-list :lang=ja`）。IPAGothic か Noto CJK があればよい |
| ウィンドウに枠がない・必ず原点に出る | Xvfb にウィンドウマネージャがいないため。**位置が決定的になるので好都合** |
| C++ をビルドしようとしてヘッダがない | PySide6 の wheel には Qt のライブラリ本体は入っているがヘッダは入っていない。`qt6-base-dev` を別途入れる |
| `doc.qt.io` / `wiki.qt.io` の取得が 403 | 自動取得を弾かれる。検索結果と、**インストール済みの実物の introspection** で補う |
| offscreen で毎回出る警告 | `propagateSizeHints` はプラットフォームの都合。無視してよいノイズとして除外リストに入れてある |

> 403 の件は結果的に良い方向に働きました。
> 公式ドキュメントが読めないので**実物を直接調べるしかなく**、
> それが「ドキュメントより確実な一次情報」になったからです。

## 5. Qt6 教材ならではの、説明の工夫

共通ルール 5 節に書いたこと以外で、この教材で効いたものです。

### 5-1. スタイルを固定し、そのことを本文で明言する

Qt Widgets の見た目は OS ごとに変わります。
章をまたいで見た目を揃えるため、全スクリーンショットを `Fusion` スタイルで撮り、
第 2 章で次のように書きました。

> あなたの Windows / macOS では、ボタンの角の丸みや配色が違って見えるはずですが、
> **構造とコードはまったく同じ**です。心配しないでください。

これを書かないと、読者は「自分の環境がおかしいのでは」と疑い始めます。

### 5-2. イベントループを最初に教える

第 2 章でイベントループを扱ったのが効きました。
「なぜ `app.exec()` が要るのか」「なぜ重い処理を書くと固まるのか」が、
ここを理解していると全部つながります。

**GUI 教材では、部品の使い方より先に「プログラムがなぜ終わらないのか」を説明してください。**

### 5-3. Python と Qt でオブジェクトの寿命の考え方が違う、を独立した章にする

「ウィンドウが一瞬で消える」はエラーが一切出ないため、初心者が自力で解決できません。
第 7 章を丸ごとこれに充て、**エラーが出ないことこそが問題である**と明示しました。

C++ の付録章を書いたとき、この悩みが C++ には無い（GC がないぶん素直）ことが分かり、
説明が一段はっきりしました。**別の言語から見ると、その言語固有の複雑さが見えます。**

### 5-4. 逆引きの地図を置く

第 5 章のウィジェット図鑑は、クラス名ではなく
「操作させたい／入力させたい／選ばせたい／見せたい／まとめたい／たくさん並べたい」
の 6 分類から引ける形にしました。学習者はクラス名を知らない状態で来るからです。
